# Модуль Клиентов (Clients)

**Создан:** 2026-04-27 (предположительно)  
**Статус:** Реализован (базовая модель)  
**Зависимости:** нет (базовый модуль)

## Назначение
Модуль `clients` представляет собой CRM-ядро системы. Он хранит информацию о клиентах компании «Основа» (доставка питьевой воды). Каждый клиент — это физическое лицо или организация, которая заказывает воду.

## Архитектура

### Модель `Client`

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | CharField(85) | ФИО клиента (обязательно) |
| `phone` | CharField(12) | Номер телефона (уникальный) |
| `address` | CharField(120) | Адрес доставки |
| `balans` | IntegerField | Предоплата (депозит) клиента. Может быть отрицательным (долг). |
| `note` | TextField(255) | Примечание (например, «аллергия на пластик») |
| `latitude` | DecimalField(9,6) | Широта геопозиции (добавлено в P1) |
| `longitude` | DecimalField(9,6) | Долгота геопозиции (добавлено в P1) |
| `tg_id` | BigIntegerField | Telegram ID для связи с ботом (добавлено в P1) |
| `created_at` | DateTimeField | Время регистрации в системе (auto_now_add) |
| `updated_at` | DateTimeField | Время последнего редактирования (auto_now) |

**Уникальность:** Поле `phone` уникально, чтобы избежать дубликатов клиентов.

## Геопозиция
Поля `latitude` и `longitude` добавлены в рамках задачи **P1**. Они позволяют:
- Сохранять координаты, присланные клиентом через Telegram (например, локация)
- Рассчитывать расстояние до клиента для автоматического распределения заказов (P3)
- Отображать клиентов на карте в админке

**Формат:** Decimal с точностью до 6 знаков после запятой (пример: `39.654321`).

## Telegram ID
Поле `tg_id` добавлено в рамках задачи **P1**. Оно обеспечивает:
- Связь аккаунта в базе с пользователем Telegram-бота
- Авторизацию клиента в Telegram Mini App (P3)
- Отправку уведомлений клиенту через бота

**Особенности:** `unique=True`, `null=True` (пока не все клиенты есть в Telegram).

## Связи с другими модулями

### `accounting`
- `Client` ← `Contract` (контракты с клиентом)
- `Client` ← `Installment` (рассрочки клиента)
- `Client` ← `PaymentsInstallment` (платежи по рассрочке)

### `logistics`
- **Планируется:** `Client` → `DeliveryJournal` (чтобы знать, кому именно везём воду). Сейчас связи нет — это задача P1.

### `bot_bridge`
- Клиент может авторизоваться в боте через `tg_id`
- Бот может показывать клиенту его историю заказов и баланс

## Бизнес-логика

### Предоплата (`balans`)
- Положительное значение: клиент внёс депозит, можно списывать с него при заказах.
- Отрицательное значение: клиент должен компании (например, задержал оплату).
- Ноль: нет предоплаты.

**Использование:** При создании заказа можно автоматически списывать с `balans`, если включена опция «Оплатить с предоплаты».

### Геопозиция в работе курьера
1. Клиент присылает локацию в Telegram.
2. Бот сохраняет `latitude`/`longitude` в `Client`.
3. При создании `DeliveryJournal` система может автоматически назначить ближайшего курьера (P3).

## Админка
Модель `Client` зарегистрирована в `apps/clients/admin.py`. Доступные действия:
- Поиск по имени, телефону, адресу
- Фильтрация по наличию предоплаты
- Редактирование геопозиции (ручной ввод)
- Просмотр связанных контрактов и рассрочек

## Примеры использования

### Создание клиента
```python
from apps.clients.models import Client

client = Client.objects.create(
    name="Иванов Иван Иванович",
    phone="+998901234567",
    address="Самарканд, ул. Мирзо Улугбека, 12",
    balans=50000,
    note="Предпочитает воду без газа",
    latitude=39.654321,
    longitude=66.987654,
    tg_id=123456789
)
```

### Поиск клиента по Telegram ID
```python
client = Client.objects.get(tg_id=123456789)
```

### Обновление геопозиции из Telegram
```python
def update_client_location(tg_id, lat, lon):
    client = Client.objects.get(tg_id=tg_id)
    client.latitude = lat
    client.longitude = lon
    client.save()
```

## Ограничения и известные проблемы

1. **Нет связи с DeliveryJournal** — невозможно узнать, какому клиенту была доставка (требуется P1).
2. **Нет валидации телефона** — поле `CharField(12)` не проверяет формат номера.
3. **Нет истории изменений** — кто и когда менял данные клиента.
4. **Геопозиция не обязательна** — многие клиенты могут не иметь координат.
