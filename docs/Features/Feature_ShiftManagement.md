# Функция: Управление сменами и рейсами курьера

> Дата создания: 21.06.2026  
> Статус: ✅ Реализовано  
> Модули: `CourierMiniApp`, `BotBridge`, `Logistics`

## Зачем эта функция

Курьеру нужен удобный способ управлять своей рабочей сменой прямо из Telegram Mini App:
- Открывать/закрывать смену
- Начинать новый рейс с указанием загруженных баклажек
- Видеть статистику текущей смены в реальном времени
- Просматривать историю прошлых смен с детализацией по рейсам и заказам

**Бизнес-ценность:** Курьер полностью автономен — не нужно звонить диспетчеру для открытия смены или рейса. Вся информация о доходах и доставках доступна мгновенно.

---

## Архитектура решения

### Модель данных (уже существовала)

```
CourierShift (смена)
  ├── status: OPEN / CLOSED
  ├── cash_total, card_total (автоматически обновляются сигналами)
  └── trips (связь 1:N)
       │
       └── CourierTrip (рейс)
            ├── status: ACTIVE / DONE
            ├── full_loaded (загружено баклажек)
            └── orders (связь 1:N)
                 │
                 └── Order (заказ)
                      ├── status: PENDING / DELIVERED / CANCELLED
                      ├── payment_type: CASH / CARD / BONUS
                      └── items (позиции заказа)
```

**Почему такая структура:**
- **Смена** — контейнер для всех рейсов за день. Финансы агрегируются на уровне смены.
- **Рейс** — одна загрузка машины. Курьер может делать несколько рейсов за смену.
- **Заказ** — привязан к рейсу, но может быть создан до начала рейса (в пуле).

### Логика отображения кнопки (3 сценария)

```javascript
// Случай А: нет активной смены
if (!hasShift) {
  return <button onClick={handleOpenShift}>🌅 Открыть смену</button>
}

// Случай Б: смена есть, но нет активного рейса
if (hasShift && !hasActiveTrip) {
  return <button onClick={() => setShowModal(true)}>🚚 Начать новый рейс</button>
}

// Случай В: есть активный рейс
if (hasShift && hasActiveTrip) {
  return (
    <div>
      Рейс #{activeTrip.id} в процессе →
      <button onClick={() => navigate('/trip')}>Перейти к рейсу</button>
    </div>
  )
}
```

**Почему именно так:**
- Курьер не может начать рейс без смены (бизнес-правило)
- Нельзя начать второй рейс пока первый активен (избегаем путаницы)
- Если рейс активен, кнопка "Начать рейс" **скрывается** — вместо неё показываем навигацию

### Модальное окно "Начать рейс"

```javascript
<input 
  type="number" 
  min="1" 
  placeholder="Сколько баклажек загружено?"
  value={fullLoaded}
  onChange={(e) => setFullLoaded(e.target.value)}
/>
<button onClick={handleOpenTrip}>Начать</button>
```

**Почему курьер вводит число сам:**
- Склад может быть удалённым или курьер грузит из дома
- Доверяем курьеру — проверка будет при закрытии рейса (сверка остатков)

## Backend: API эндпоинты

### 1. GET `/api/bot/shifts/current/`

**Что возвращает:**
```json
{
  "shift": {
    "id": 42,
    "date": "2026-06-21",
    "status": "OP",
    "cash_total": 450000,
    "card_total": 320000
  },
  "shift_stats": {
    "orders_count": 12,
    "water_delivered": 15
  },
  "trips": [
    {
      "id": 5,
      "status": "AC",
      "full_loaded": 20,
      "summary": {
        "delivered": 12,
        "full_remain": 8,
        "empty_received": 10
      }
    }
  ]
}
```

**Логика подсчёта `water_delivered`:**
```python
water_delivered = OrderItem.objects.filter(
    order__trip__shift=shift,
    order__status=Order.Status.DELIVERED,
    product__type_product=Product.TypeProduct.WATER  # только тип 'WT'
).aggregate(total=Sum('quantity'))['total'] or 0
```

**Почему только WATER (WT):**
- Тара (BOTTLE) и аксессуары (ACCESSORY) не считаются как "доставленная вода"
- Курьеру важно знать сколько баклажек он развёз, а не сколько пустых тар продал

### 2. GET `/api/bot/shifts/history/`

**Query params:**
- `date_from` (YYYY-MM-DD) — начало периода
- `date_to` (YYYY-MM-DD) — конец периода

**Что возвращает:**
Массив смен с полной вложенной структурой: смены → рейсы → заказы → позиции.

**Оптимизация:**
```python
# Используем prefetch_related для избежания N+1 запросов
shifts = CourierShift.objects.filter(
    courier=courier,
    date__gte=date_from,
    date__lte=date_to
).prefetch_related(
    'trips__orders__items__product',
    'trips__orders__client'
).order_by('-date')
```

**Почему `order_by('-date')`:**
- Свежие смены показываются первыми (обратная хронология)
- Курьеру чаще нужна недавняя история, чем старая

## Исправленные баги

### Баг #1: Неправильные статусы рейсов

**Симптом:**
```javascript
// В коде было:
const activeTrip = trips.find(t => t.status === 'ACTIVE')
// Но бэкенд возвращал:
{ "status": "AC" }  // сокращённый код из модели
```

**Причина:**
Django модель `CourierTrip` использует `TextChoices`:
```python
class Status(models.TextChoices):
    ACTIVE = 'AC', 'В пути'
    DONE   = 'DN', 'Завершён'
```

Первое значение ('AC', 'DN') — это то, что хранится в БД и возвращается в API.

**Решение:**
```javascript
// Изменили на коды из модели:
const activeTrip = trips.find(t => t.status === 'AC')
const isDone = trip.status === 'DN'
const isActive = trip.status === 'AC'
```

**Как не допустить снова:**
- Всегда проверяй что возвращает API (через DevTools → Network)
- Документируй коды статусов в комментариях:
  ```javascript
  // Статусы рейса: 'AC' (ACTIVE), 'DN' (DONE)
  ```

### Баг #2: AttributeError в ShiftHistoryView

**Симптом:**
```
AttributeError: 'Order' object has no attribute 'total_price'
```

**Причина:**
В модели `Order` нет поля `total_price` — есть метод `get_total_price()`:
```python
class Order(models.Model):
    def get_total_price(self):
        return self.items.aggregate(total=Sum('total_price'))['total'] or 0
```

**Решение:**
```python
# ДО (ошибка):
'total_price': order.total_price

# ПОСЛЕ (правильно):
'total_price': order.get_total_price()
```

**Почему метод, а не поле:**
- `total_price` вычисляется динамически из позиций заказа
- Хранить его в БД — дублирование данных (нарушение нормализации)
- Если позиция изменится, поле устареет → метод всегда актуален

## Дальнейшие улучшения (техдолг)

1. **Кэширование статистики смены**
   - Сейчас: каждый запрос пересчитывает `water_delivered` через агрегацию
   - Лучше: кэшировать в Redis с TTL 60 секунд
   - Выигрыш: снижение нагрузки на БД при частых обновлениях страницы

2. **Пагинация истории смен**
   - Сейчас: возвращаем все смены за период (может быть 100+)
   - Лучше: пагинация по 20 смен + infinite scroll
   - Выигрыш: быстрая загрузка первой страницы

3. **Экспорт истории в PDF**
   - Курьер может захотеть распечатать отчёт за месяц
   - Кнопка "Скачать PDF" → генерация через ReportLab

4. **Push-уведомления при закрытии смены**
   - Когда диспетчер закрывает смену курьера → уведомление в Telegram
   - Используем `notify.py` из `bot_bridge`
