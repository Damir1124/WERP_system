# Модуль: Курьерский бот (кнопочный поток) — `tg_bot/`

## Зачем этот модуль
Курьер должен иметь возможность выполнить **весь** рабочий цикл (смена → рейс →
пул → взять → доставить) прямо из чата Telegram, без открытия Mini App. При этом
Mini App (`frontend/courier`) остаётся рабочим — кнопка «🌐 Mini App» всегда доступна
в главном меню. Это **гибридный** подход: кнопки для быстрых действий, Mini App для
сложных экранов (карта, детальный список заказов).

> 💡 **Почему гибрид, а не «только кнопки»:** кнопками неудобно показывать карту
> геопозиций и многопозиционную корзину. Но 90% операций курьера — это короткие
> действия, которые быстрее делать кнопками, чем открывать веб-приложение. Поэтому
> бот дублирует весь сценарий, а Mini App остаётся опциональным.

## Архитектура потока

```
🟢 Открыть смену  ──POST /shifts/────────────────────► CourierShift (OP)
        │
🚀 Начать рейс    ──POST /trips/ {full_loaded}────────► CourierTrip (AC)
        │
📦 Пул заказов    ──GET  /courier/pool/────────────────► список PENDING заказов
        │
   [взять]         ──POST /courier/pool/<id>/assign/───► Order.trip = активный рейс
        │
✅ Подтвердить     ──POST /courier/orders/confirm/──────► Order (DL) + списание тары
        │
🏁 Закрыть рейс   ──POST /courier/trips/<id>/close/────► CourierTrip (DN)
        │
🔒 Закрыть смену  ──POST /courier/shifts/<id>/close/───► CourierShift (CL)
```

Все эндпоинты уже существовали в `apps/bot_bridge/views.py` — бот лишь дёргает их
через `api_client` с заголовком `X-Telegram-ID`. **Нового бэкенда не потребовалось.**

## Файлы и их роль

| Файл | Роль |
|------|------|
| `tg_bot/routers/courier.py` | Все обработчики: reply-кнопки меню + inline-кнопки заказов + FSM доставки |
| `tg_bot/keyboards/courier.py` | Адаптивная reply-клавиатура + inline-клавиатуры (пул, детали, рейс, подтверждение) |
| `tg_bot/states/courier.py` | FSM-состояния: `CourierTripStart` (ввод `full_loaded`), `CourierDeliverOrder` (пошаговый ввод тары) |
| `tg_bot/routers/courier_create_order.py` | FSM создания заказа курьером (не трогали, работает как раньше) |

## Главное меню (адаптивное)
`keyboards/courier.py → get_courier_main_keyboard(has_shift, has_trip)` строит кнопки
в зависимости от состояния:
- **Нет смены** → «🟢 Открыть смену»
- **Смена, нет рейса** → «🚀 Начать рейс»
- **Рейс активен** → «📦 Пул заказов», «🚚 Мой рейс», «✅ Подтвердить доставку»

Плюс всегда доступны «📋 Смены и рейсы», «👥 Коллеги», «🌐 Mini App», «🆘 Помощь».

> 💡 **Почему адаптивное меню:** курьер не должен видеть кнопку «Начать рейс»,
> пока не открыта смена — иначе он запутается в последовательности действий.
> Состояние берётся одним запросом `GET /courier/trip/current/`.

## Подтверждение доставки (экран редактирования, FSM `CourierDeliverOrder`)
При нажатии «✅ Доставить» (`deliver_order_{id}`) открывается **экран редактирования
заказа** — полный аналог `OrderConfirm.jsx` из Mini App, но на кнопках:

1. Для каждой позиции заказа бот строит степперы (кнопки `➖` / `➕`):
   - **Не-вода** (`product_type` ≠ `WATER`/`BOTTLE_20L`): редактируется только
     `quantity` (количество) — `d_qty_{item_id}_{m|p}`.
   - **Вода** (`WATER` / `BOTTLE_20L`): три поля тары — `обмен` (`d_ex_`),
     `с тарой` (`d_sw_`), `брак` (`d_df_`), каждое со своим `➖`/`➕`.
2. Значения по умолчанию: для воды `обмен = заказанное количество`, остальные = 0;
   для не-воды `quantity = заказанное количество`.
3. Валидация при каждом нажатии (`adjust_edit`): количество/обмен ≥ 1, продажа с
   тарой не может превышать обмен, брак ≥ 0. При нарушении — `answer(show_alert=True)`
   и значение не меняется.
4. Кнопка «✅ Подтвердить доставку» (`d_confirm`) шлёт
   `POST /courier/orders/confirm/` с телом
   `{"order_id": id, "confirmed": true, "items": [{item_id, exchange_qty, sell_with_qty, defective_qty, quantity?}, ...]}`
   (поле `quantity` передаётся только для не-воды).
5. Кнопка «⬅️ Назад» (`d_cancel`) **не отменяет заказ** — лишь возвращает к карточке
   заказа. Отмена заказа доступна отдельной кнопкой «❌ Отменить заказ» в карточке.

> 💡 **Почему экран на кнопках, а не текстовый ввод:** бэкенд (`OrderConfirmationView`)
> требует `exchange_qty != 0` для воды — иначе нельзя корректно списать тару со склада
> и посчитать `empty_received` в `CourierTrip.get_trip_summary()`. Степперы дают тот же
> результат, что и Mini App, но быстрее и без ввода текста. Состояние FSM —
> `CourierDeliverOrder.waiting_for_edit` (одно состояние на весь экран).

> ⚠️ **Важная деталь FSM:** в `routers/courier.py` **нет** catch-all обработчика
> `@router.message()` без фильтров. Если бы он был, он перехватывал бы текстовые
> сообщения, предназначенные FSM создания заказа (`courier_create_order.py`,
> зарегистрирован позже в `bot.py`), и ломал бы его. Поэтому несовпавшие сообщения
> просто игнорируются и доходят до нужного роутера.

## Кнопки заказов в «Мой рейс»
При открытии «🚚 Мой рейс» (`show_current_trip`) каждый заказ рейса падает
отдельной inline-кнопкой. Формат метки (`build_trip_order_label`):

```
{статус} №{id} | {сумма_количеств_позиций} | {адрес_или_локация}
```

- `статус` — `✅` для доставленного (`DL`) или `⏳` для в пути (`PD`).
- `сумма_количеств_позиций` — сумма `quantity` по всем `items` (например, «2»).
- `адрес_или_локация` — `delivery_address_text` → `client_address` → `📍 локация`
  (если заданы координаты, но нет текста). Обрезается до 24 символов.

Пример: `⏳ №423 | 2 | ул. Домодедово`.

Нажатие на кнопку (`trip_order_{id}`) открывает **карточку заказа**
(`build_order_detail_text`) — клиент, телефон, адрес, товары, сумма, тип оплаты,
время создания — и inline-кнопки, аналогичные Mini App (`OrderConfirm.jsx`):

| Кнопка | callback | Действие |
|--------|----------|----------|
| ✅ Доставить | `deliver_order_{id}` | Запуск FSM `CourierDeliverOrder` (см. выше) |
| ❌ Отменить заказ | `trip_cancel_{id}` | `POST /courier/orders/confirm/` `{"confirmed": false}` → `Order.CANCELLED` |
| ↩️ Вернуть в пул | `return_order_{id}` | `POST /courier/pool/{id}/return/` → заказ снят с рейса |
| ⬅️ Назад | `back_to_trip` | Возврат к списку заказов рейса |

После отмены/возврата список рейса перерисовывается (`show_current_trip`).

> 💡 **Почему заказы — это кнопки, а не текст:** курьеру нужно быстро выбрать
> конкретный заказ из рейса одним тапом, как в Mini App. Callback `trip_order_{id}`
> передаёт ID без лишнего ввода текста.

## Скрытая команда «Сводка по адресам» (агрегация)

Курьер может ввести **скрытую команду** `/сводка` (или `/agg`), чтобы увидеть
агрегацию своих взятых заказов по адресу общежития (блок → этаж, общее
количество воды на этаж).

**Почему скрытая:** команда не выводится в меню и доступна только курьеру.
Доступность гарантируется фильтром `role == 'courier'` в `tg_bot/bot.py` —
оператор, владелец и клиент её не увидят и не смогут вызвать.

### Стандарт ввода адреса общежития
```
Блок A, 3 этаж, комната 12
```
- **Блок** — латинская буква A–Z или цифра (обязательно)
- **Этаж** — целое число (обязательно)
- **Комната** — целое число (для агрегации не обязательна)
- Разделители любые; синонимы: «блок/корпус/подъезд», «этаж/эт.», «комната/комн./кв./№»
- Примеры: `Блок A, 3 этаж, комната 12`, `Блок B 5 эт. комн. 7`, `A 3 12`

### Поток
```
/сводка ──GET /courier/orders/aggregate/──► агрегация PENDING-заказов курьера
        │                                    в активном рейсе по адресу
        ▼
📦 Сводка по адресам
🏢 Блок A
   3 этаж — 4 шт
      комната 12 — 3 шт
      комната 15 — 1 шт
🏢 Блок B
   5 этаж — 3 шт
      комната 7 — 3 шт
```
Количество воды **суммируется по этажу** (общее кол-во на этаж), единица — «шт».
Под этажом показывается детализация по комнатам (сколько шт в каждой).
Заказы с нераспознанным адресом выводятся **отдельными inline-кнопками**
(по образцу `get_pool_inline_keyboard`) — курьер может открыть каждый и посмотреть адрес.

### Реализация
- `apps/logistics/services.py` — `parse_dormitory_address()` (парсер) и
  `aggregate_orders_by_address()` (группировка по блоку+этажу, сумма воды 19л).
- `apps/bot_bridge/views.py` — `CourierOrdersAggregateView` (`GET /courier/orders/aggregate/`).
- `tg_bot/routers/courier.py` — обработчик `Command("сводка")` / `Command("agg")`.
- Тесты: `tests/logistics/test_dormitory_aggregation.py`.

## ⚠️ Известные ограничения
- Нет карты геопозиций (только текстовый адрес) — для этого открывайте Mini App.
- Многопозиционный заказ через бот создаётся упрощённо (водная позиция + опц. тара);
  полноценная корзина — в Mini App / админке.
- Сообщения длиннее 4096 символов Telegram не проглатит — список заказов рейса
  ограничен 25 шт. на одно сообщение.
