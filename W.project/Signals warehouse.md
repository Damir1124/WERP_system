# Объяснение работы склада

## Модели данных (models.py)

### StockBalance
Это модель, которая отслеживает текущее количество продуктов на складе:
- `product` - ссылка на продукт
- `quantity` - сколько товара сейчас на складе
- `last_received_date` - когда последний раз добавляли товар
- `last_departure_date` - когда последний раз забирали товар со склада

### StockMovement
Это модель, которая записывает историю всех движений товаров:
- `sold_product` - какой продукт двигался
- `contract` - по какому контракту (если есть)
- `operation_type` - тип операции: "Buy" (покупка) или "Sell" (продажа)
- `quantity` - сколько товара участвовало в операции
- `data` - дата операции
- `note` - примечание о операции

## Обработчики сигналов (signals.py)

В Django сигналы - это события, которые происходят при изменении данных. Мы используем их, чтобы автоматически изменять остатки на складе, когда создаются или изменяются продукты, доставки или контракты.

### 1. Создание StockBalance при создании продукта
```python
@receiver(post_save, sender=Product)
def create_stock_balance_product(sender, instance, created, **kwargs):
```
Когда создается новый продукт, автоматически создается запись о нулевом остатке этого продукта на складе.

### 2. Отслеживание изменений до сохранения
```python
@receiver(pre_save, sender=SubjectContract)
def track_subject_contract_changes(sender, instance, **kwargs):
```
```python
@receiver(pre_save, sender=DeliveryJournalProducts)
def track_delivery_journal_changes(sender, instance, **kwargs):
```
Эти функции запоминают старые значения перед изменением записей, чтобы мы могли сравнить, что изменилось.

### 3. Обновление остатков при доставке товаров
```python
@receiver(post_save, sender=DeliveryJournalProducts)
def update_stock_balance_on_delivery(sender, instance, created, **kwargs):
```
Эта функция:
- При новой доставке: уменьшает количество товара на складе (продажа)
- При изменении доставки:
  - Если количество увеличили: дополнительно уменьшает остаток на складе
  - Если количество уменьшили: возвращает товар на склад

### 4. Обновление остатков по данным из контрактов
```python
@receiver(post_save, sender=SubjectContract)
def update_stock_balance_on_subject_contract(sender, instance, created, **kwargs):
```
Эта функция:
- При новом контракте:
  - Если это контракт продажи (SELL): уменьшает количество на складе
  - Если это контракт покупки (BUY): увеличивает количество на складе
- При изменении контракта:
  - Вычисляет разницу между старым и новым количеством
  - Изменяет остаток на складе соответственно

## Как это всё работает вместе

1. **Создание продукта:**
   - Создается продукт в базе данных
   - Автоматически создается запись в StockBalance с нулевым количеством

2. **Закупка товара (контракт BUY):**
   - Создается запись SubjectContract с типом BUY
   - Автоматически увеличивается количество продукта на складе в StockBalance
   - Создается запись в StockMovement с типом BUY

3. **Продажа товара (контракт SELL):**
   - Создается запись SubjectContract с типом SELL
   - Автоматически уменьшается количество продукта на складе в StockBalance
   - Создается запись в StockMovement с типом SELL

4. **Доставка товара:**
   - Создается запись DeliveryJournalProducts
   - Автоматически уменьшается количество продукта на складе
   - Создается запись в StockMovement с типом SELL

5. **Изменение контракта или доставки:**
   - При изменении количества система:
     - Сохраняет старое значение
     - Вычисляет разницу
     - Корректирует остаток на складе
     - Создает запись о движении товара с соответствующим типом

## Логирование

Мы используем `logger` для записи важной информации в лог-файлы. Это помогает отслеживать:
- Что происходит в системе
- Когда происходят ошибки
- Какие изменения происходят с остатками

## Важные моменты для понимания:

1. **Проверки достаточного количества** - перед каждым списанием мы проверяем, хватает ли товара на складе.

2. **Отслеживание старых значений** - мы используем `pre_save` чтобы запомнить старые значения перед изменением.

3. **Типы операций** - у нас есть два основных типа:
   - `BUY` - для закупок и возвратов (увеличение количества)
   - `SELL` - для продаж и корректировок (уменьшение количества)

4. **Отметки времени** - мы обновляем даты последнего поступления и последнего списания товара.

5. **Логи** - мы записываем информацию о всех действиях, чтобы потом можно было понять, что произошло.
