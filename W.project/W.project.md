# Проект: Osnova
## 1. Введение
- Название проекта: ERP-система Osnova
- Цель проекта: Автоматизировать рутинные процессы и ведение учета
- Заказчик: Eco Life
- Ответственный исполнитель: Дамирка
---
## 2. Описание системы
```bash
WERP_project/
├── manage.py
├── WERP_project/  # Корневые настройки (settings, urls, wsgi, asgi)
└── apps/
    ├── clients/   # Модуль учета клиентов
    ├── products/  # Модуль учета позиций (ассортимент, продукты)
    ├── workers/   # Модуль учета сотрудников (работники, курьеры, прочие)
    ├── warehouse/ # Модуль склада (баланс, движение товаров, гараж)
    ├── logistics/ # Модуль логистики (учет доставки, движения позиций)
    └── accounting/# Модуль бухгалтерии
```


### 2.1 Основные модули
- Учет клиентов
- Учет позиций
- Учет работников
- Склад
	- Баланс единиц по позиционно
	- Движение
- Логистика
- Бухгалтерия
	- учет контрактов
	- учет рассрочки клиентов
	- учет заработной платы работников, курьеров
	- учет прибыли
		- дневной по рейсово для каждого курьера
		- месячный в совокупности
	- учет расходов
	- учет доходов
		- дневной, недельный, месячный
### 2.2 Основные роли пользователей
- **Админ** - управляет настройками и пользователями
- **Бухгалтер** - управляет финансами, контрактами, мониторит статистику
- **Курьер** - мониторит заказы (Osnova Plus) 
- **Оператор** (Osnova Plus)
## 3. Требования к функционалу
### 3.1 Учет клиентов
#### Описание модуля
**Клиент** - Физическое или Юридическое лицо пользуясь нашими услугами/продуктами в плане:
- В большом количестве **("Оптовики")**
- Чаще чем остальные / Постоянно **(Постоянный клиент)**
- Офисы, предприятия, учреждения **(Юр. Лицо)**
- Знакомые, друзья персонала / руководства **(Свои)**
---
##### **Вкладка 1**
###### Описание
- Просмотр клиентов, ведение учета
###### Хранение данных
 - ФИО, телефон, адрес, баланс, заметка
###### Функционал
- Добавление, Редактирование, Удаление клиентов
### 3.2 Учет продуктов
#### Описание модуля
**Продукт** - часть ассортимента, будь то продовольственный или непродовольственный товар:
- **Аксессуар** - помпы, подстаканники...
- **Кулер** - Виды кулеров для воды
- **Вода** - доступная в разных объемах
- **Тара** - 20 литровая тара которая может продавятся только вместе с водой, клиентам у которых нет своей 
---
##### **Вкладка 1**
###### Описание
- Просмотр и учет ассортимента позиций 
###### Хранение данных
- Наименование продукта, тип продукта, стоимость
###### Функционал
- Добавление, Редактирование, Удаление позиций
- Возможность сортировки по кол-во продаж
### 3.3 Учет работников
#### Описание модуля
**Работник** - штатный сотрудник, нанятый человек:
- Упаковщик - работающий на заводе
- Курьер - развозит воду 
- Прочие сотрудники...
---
##### **Вкладка 1**
###### Описание
- Учет всех работников включая позицию, зароб. плату...
###### Хранение данных
 - ФИО, тип сотрудника, дата начала начисления зароб. платы, машина(у курьера), дата прихода
###### Функционал
- Добавление, Редактирование, Удаление 
- Возможность сортировки по количеству обслуженных клиентов
### 3.4 Склад
#### Описание модуля
**Склад** - то раздел где будет происходить учет автопарка, продуктов и его движение по позиционно:
- Приход, по контракту, поставке
- Уход позиций по продажам, контрактам (пока что только тара )
---
##### **Вкладка 1**
###### Описание
- Учет баланса и остатков на складе по позициям
###### Хранение данных
- Наименование позиции, остаток на складе, последняя дата прихода, последняя дата ухода
###### Функционал
- Остаток на складе - динамически обновляемое по операциям со  'Вкладка 2', путем вычисления разницы по типам операций и поля 'количество'
- Простое отображение подсчитанного со вкладки 2 по позиционно
##### **Вкладка 2**
###### Описание 
- Запись всех приходов уходов по типу закупки новых тар и продажей тар вместе с водой(Последнее будет браться с журнала отчетов курьеров)
###### Хранение данных
- Наименование позиции, контракт(С таблицы контракт), имя курьера, тип операции(Приход, уход), количество, дата операции
###### Функционал
- Отображение всех операций связанных с приходом и уходом
##### **Вкладка 3**
###### Описание
- Гараж, учет машин и их временных владельцев, техническое состояние
###### Хранение данных
- Наименование машины, номерной знак, Имя курьера, пробег, год выпуска
###### Функционал
- Отображение всех машин их пробег и возможная привязанность к курьеру(Учет работников - Тип курьер)

### 3.5 Логистика
#### Описание модуля
**Логистика** - все то что связанно с доставкой
- Взятие, привоз, возврат позиций
- Сопоставление движения позиций с отчетами от курьеров
- Сопоставление, Фиксирование и подсчёт суммы на которую взято и продано товара
---
##### **Вкладка 1**
###### Описание
Данные которые пишутся в журнал будут писаться в эту вкладку - вкладку Log
###### Хранение данных
- Имя курьера, тип операции(Взял, Привез), количество, дата
- Имя курьера, подсчитанное число, поля ведения записи операций для подсчёта числа, дата
###### Функционал
- На рассмотрение 2 варианта: 
	- Журнал движения тар по типу 'взял' / 'привез' в ежедневном ведении 
	- Журнал движения тар по полю в котором будет подсчет а ответ в другом поле в ежедневном ведении, на каждого курьера по вкладке
##### **Вкладка 2** 
###### Описание 
Здесь будут отображается подытоженные данные с вкладки 1, как статистика покурьерно(наверно djoins можно)
###### Хранение данных
- Имя курьера, всего продано за день / воды / тар / кулеров
###### Функционал
- Фильтрация по датам
- Ежедневная покурьерно отчётность
##### **Вкладка 3**
###### Описание
- То где будут вносится отчеты от курьеров
- Отчетов может быть несколько
- В одном отчете несколько записей 
- В одной записи может быть несколько продуктов
- У каждого продукта может быть свое количество
###### Хранение данных
- Дата, описание, кулер, помпа, тара, вода, сумма, тип оплаты(нал, карта, бонус(как расход тоже считается), по умолчанию нал)
###### Функционал
- Журнал отчетов в ежедневном ведении, в котором будут записывается отчет курьеров о продажах, на каждого курьера по вкладке, и затем сверятся с журналом движения по привозу, увозу, возврату 
- Динамическое отображение суммы(выручки) за день, и последующее добавление этой суммы в финансы во вкладку учета выручки курьеров в день. Страница журнала должна обнулятся каждый день при смене через день 
### 3.6 Бухгалтерия
#### Описание модуля
Бухгалтерия - все то что касается движения финансов, прибыли, расходов, доходов, путем отслеживания таких тем как:
- Учет доходов и расходов по контрактам 
- Учет рассрочки клиентов
- Учет начисления заработной платы работников
- учет прибыли
- учет расходов 
- учет доходов
---
##### **Вкладка 1**
###### Описание
- **Управление контрактами**, они могут быть на поставку и на прием (в плюс и в минус)
- У контрактов могут быть продукты и прочие позиции которые мы закупаем или продаем и их может быть несколько 
###### Хранение данных
Оснавная таблица создания контрака:
- описание, дата, прикрепленные документы, тип(плюс или минус), сумма
Список того что входит в продажу / покупку контракта:
- Описание, тип продукта, количество, cумма(необязательна для заполнения)
###### Функционал
- Добавление, Редактирование, Удаление
##### **Вкладка 2**
###### Описание
- **Учет клиентов** взявших товар в **рассрочку**
- Учет выплат по рассрочке
###### Хранение данных
- отдельный модуль списка клиентов с рассрочкой:
	- дата оформления, ФИО, номер телефона, товар, сумма выплаты, дата последней выплаты, остаток суммы 
- лог оплаты рассрочки по клиентам(ввод данных, без отображения):
	- дата взноса, ФИО, сумма взноса 
###### Функционал
- автоматический подсчет остатка(по логу), напоминания об оплате к приходу даты оплаты(бухгалтеру)
- Автоматическая смена статуса при погашении рассрочки(когда остаток суммы будет 0)
##### **Вкладка 3**
###### Описание
- **Выплаты сотрудникам**, также могут быть штрафы для них
###### Хранение данных
- Сотрудники и их баланс
	- Работник, к какому числу выплата, сумма выплаты баланс(в течении текущего месяца), примечание
- Лог выплат по сотрудникам(история выплат, ввод данных и показ истории выплат по каждому сотруднику отдельно):
	- Дата, сотрудник, сумма выплаты(тип в плюс или в минус, бонус), примечание
###### Функционал
- Начисление зарплаты, возможность вычетов и прибавок
- Обнуление баланса через месяц с момента последней выплаты, не учитывая тип 'бонус'
##### **Вкладка 4**
###### Описание
- **Учет прибыли** - учет всех положительных сумм сумм приходящих в кассу
- по дневной учет прибыли с продаж и с контрактов, и штрафов(тип минус с зарплат)
###### Хранение данных
- Общая статистика по товарам и контрактам отдельно(автоматически подсчитывается с лога):
	1. Товар, количество продаж, прибыль с продаж
	2. кол-во контрактов в плюс, прибыль с контрактов
	3. кол-во штрафов, прибыль со штрафов
- Лог прибыли по продажам, контрактам, штрафам(операции в плюс автоматически добавляются в лог):
	1. Дата, Товар, кол-во, сумма выручки
	2. Дата, контракт, сумма контракта
	3. Дата, работник, сумма штрафа
###### Функционал 
- Автоматически обновляется инфа и подсчитываются данные по мере добавления записей в плюс в других модулях
##### **Вкладка 5**
###### Описание
- **Учет расходов - учет всех отрицательных  сумм приходящих в кассу
- по дневной учет расходов по выплатам на: зарплату, контракты, бонусы(работникам)
###### Хранение данных
- Общая статистика по выплатам на: зарплату, контракты, бонусы(автоматически подсчитывается с лога):
	1. Работник, сумма выплат
	2. кол-во контрактов в минус, сумма выплат
	3. кол-во бонусов, сумма выплат
- Лог прибыли по выплатам на: зарплату, контракты, бонусы(операции в плюс автоматически добавляются в лог):
	1. Дата, Работник, сумма выплаты
	2. Дата, контракт, сумма контракта
	3. Дата, работник, сумма бонуса
###### Функционал 
- Автоматически обновляется инфа и подсчитываются данные по мере добавления записей в плюс в других модулях
##### **Вкладка 5**
###### Описание
- **Учет доходов** - разница между прибылью и расходами
- по дневной учет  по доходам с: товаров, контрактов, штрафов
###### Хранение данных
- Общая статистика по доходам с: товаров, контрактов, штрафов(автоматически подсчитывается путем: лог доходов минус лог расходов(штраф - бонус)):
	1. Товары, cумма 
	2. Контракты, сумма
	3. Штрафы, сума
###### Функционал 
- Автоматически обновляется инфа и подсчитываются данные по мере добавления записей в плюс в других модулях
